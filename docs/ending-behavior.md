# 结局演示的两个“看起来像 BUG”的原机行为

> **结论先行：两者都是原版 `FD2.EXE` 的既定行为，不是移植缺陷，不需要改代码。**
> 本文记录现象、根因、证据和玩家侧应对方式，避免重复排查。
> 原机地址以 `FD2.EXE.i64` 为准；逐指令还原记录见 `PROGRESS.md` §91 / §92。

## 1. 结局只介绍 2–3 个人的去向

### 现象

结局对白之后，依次显示“姓名/职业 + 各人去向”的名单屏，但只出现 2–3 人就直接进入
尾声字幕（宣传企划、地图、程式等人员表）。

### 根因

去向文本在 `FDTXT.DAT` 的 **res31**（全文见 [dialogue.md](dialogue.md) §res31）：

| sub | 内容 |
|---:|---|
| 10 / 11 | “姓名：” / “職業：” 标签 |
| 12..43 | **32 名队员各自的去向** |
| 44 | 总别离文字（演示开头淡入时预绘） |
| 45 | 最后一段收束文字 |

展示由 `figure_showcase_run()`（原机 `0x31C49`）负责，被 `ending_demo_run()`
（`0x31529`）调用一次。循环上界是**当前队伍人数** `dword_53BFB`，不是 res31 的段数：

```c
for (j = (int)dword_53BFB - 1; j >= 0; --j) { ... }
```

`dword_53BFB` 由 `unit_add()` 递增、读档时从存档头恢复；全收集通关是 **32**，
因此没有人按键时应当显示 32 个个人屏，并在最后一屏（`j == 0`，`n >= 220`）改用 sub45。

**截断来自原机的按键跳过逻辑**（`src/game/figure_showcase.c:156-159`）：

```c
if (kbd_pending() != 0) {
    j = 1;
    kbd_flush();
}
```

它不跳出内层帧循环，而是把外层下标改成 `j = 1`。当前屏播完后只剩 `j = 1`、`j = 0`
两屏，所以实际只看到 **当前屏 + 2 屏 = 2–3 人**。在 `j == 1` 时按键则只剩 2 屏。

### 为什么很容易误触

`msg_show_lines()` 每次结尾都会 `kbd_flush()`（`src/game/msg.c:153-164`），但**最后一次
结局对白之后到名单开始之间没有任何 flush**：500 ms 延时 + 3 轮淡出 + 97 帧 blit +
2000 ms 延时 + 40 帧循环 + 200 帧循环，合计十几秒。玩家为翻对白按下的键（或系统按键
重复）会一直 pending，进入名单后立即触发跳过。

### 应对

**从最后一段结局对白出现起就不要再按键**（包括回车、空格、方向键）。这样可以看到
全部 32 人去向与最后的 sub45。少按键也不会改变结局内容，只是跳看名单。

### 证据

- `PROGRESS.md` §91（`2317-2335` 行）：`0x31C49` 逐指令核对离线反汇编，明确记有
  “`kbd_pending()` 为真则 `j=1` + `kbd_flush()`”。
- `src/game/figure_showcase.c:124,143-152`：`nframes = j ? 220 : 440`、
  `line_sub = n >= 220 ? 45 : rec[8] + 12`。
- 全仓库没有在结尾把 `dword_53BFB` 改成 2–3 的写入。

## 2. THE END 之后画面冻结、音乐继续、按键无响应

### 现象

全部人员介绍结束后，画面停在 THE END，BGM（track 18）继续播放，但任何游戏按键都
无响应。

### 根因

两个结束态处理函数在调用完 `ending_demo_run()` 后，就是**原机的故意死循环**：

```c
/* src/game/scene_states.c:724-726（scene_state_29，0x25757） */
sub_31529();
for (;;)
    ;                                           /* deliberate hang (original) */
```

`scene_state_26`（`0x250CC`）在 `:567-569` 是同样结构。`src/game/ending_demo.h:17-22`
和 `PROGRESS.md` §92（`2340-2341` 行）都写明“original really hangs after the demo”。

DOS 版对按键完全不读，所以确实只能 Ctrl+Alt+Del 或机箱 Reset。移植版保留这一行为，
音乐继续是因为游戏线程卡在死循环、混音线程独立运行。

### 应对（不必强杀进程）

- **标题栏关闭按钮**：默认 `--close=button` 允许，走正常 `sapp_quit()` 退出，不是
  “结束进程”（`host/main_sokol.c:459-476`）。
- **Alt+F4 / Cmd+W**：默认被拦截（避免和点叉混淆）；需要时加 `--close=both`
  （见 `README.md` 运行参数表）。
- `--autoquit-ms=N` 可用于无人值守测试时自动关窗。

注意：因为游戏线程永不返回，`fd2_engine_game_over()` 不会变真，
`host/main_sokol.c:418-420` 的自动退出不会触发；这是预期现象。

> 注：源码里虽有 Ctrl+Esc 的退出分支（`host/main_sokol.c:526-529`），但 Windows 会先
> 截获该组合键（打开开始菜单），**实际不能用来关窗**。不要再把它当作退出手段排查。

## 3. 将来若要改动

默认必须保持原机行为。若产品化需要“看全名单 / 在 THE END 按键退出”，应新增显式
开关（例如把按键跳过改为可关闭、在 THE END 绑定退出键），并保持默认关闭，
不要直接修改上述默认逻辑。
