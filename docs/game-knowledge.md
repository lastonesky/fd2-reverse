## 1. 法术命中率

### 1.1 核心公式

伤害型法术在 `unit_action_damage()`（原版 `0x1C75E`）中判定：

```c
chance = action_table[spell_id].byte2;   // 0..100
if (rand() % 100 < chance)
    命中并结算伤害;
else
    Miss;
```

- 表：`0x619FD`，每项 **7 字节**；
- `byte0..1`：基础威力（s16）
- `byte2`：命中率（0..100）
- `byte3`：效果范围
- `byte4`：半径
- `byte5`：MP/行动消耗

**命中率只由法术本身决定，不受施法者等级、智力、目标魔防/敏捷/运气、地形影响。**

### 1.2 伤害型法术固定命中率

| id | 法术 | 命中率 |
|---:|---|---:|
| 0 | 火炎術 | 90% |
| 1 | 烈炎術 | 90% |
| 2 | 炎龍術 | 90% |
| 3 | 天火術 | 85% |
| 4 | 電擊術 | 85% |
| 5 | 落雷術 | 80% |
| 6 | 轟雷術 | 80% |
| 7 | 神雷術 | 80% |
| 8 | 聖光彈 | 100% |
| 9 | 咒殺 | 50% |
| 10 | 碎岩術 | 95% |
| 11 | 地震術 | 90% |
| 12 | 裂地術 | 90% |

### 1.3 法术伤害

命中后：

```c
base = action[0..1](s16) * class_power[rec[0x20] - 1] / 10;
实际伤害 = base * 90% + rand()%100 * base / 1000;
```

- `class_power` 表在 `0x51F96`，28 项，值为 4..10：
  - 10 = 100% 威力
  - 4 = 40% 威力
- 因此**等级不影响法术伤害**；职业（`rec+0x20`）决定威力系数。
- `unit_damage()` 只扣目标 HP，**不读取目标防御/魔防**。

### 1.4 例外

- **封咒術(22)、施毒術(26)、麻庳術(27)**：不走 `byte2`，固定 **50%** 判定；命中后固定 10 点伤害并附加状态；目标职业 `+0x20 == 25/26` 时直接跳过（免疫）。
- **解毒、祛麻、攻击/防御/速度术、治疗术**：没有命中判定，合法目标必中。
- **碎岩/地震/裂地(10..12)**：对 `rec_skip()` 为真的目标直接 Miss。

### 1.5 与物理命中的区别

物理攻击在 `map_attack_resolve()`（`0x1ECC7`）使用：

```c
if (rand() % 100 < 攻击方派生DX - 防守方派生DX)
```

法术没有这个公式，也不存在“魔抗/回避”属性。

## 2. 角色记录与装备槽

角色记录 80 字节（`dword_53A45 + 80*idx`）：

| 偏移 | 内容 |
|---:|---|
| `+0x0A..+0x19` | 8 个物品槽，每槽 2 字节：`[状态, 物品ID]` |
| `+0x1F` | 种族 |
| `+0x20` | 职业（装备限制、法术威力系数） |
| `+0x21` | 等级 |
| `+0x26..+0x2A` | 已学法术/行动位图 |
| `+0x37` | 基础 AP |
| `+0x39` | 基础 DP |
| `+0x3E` | 基础 DX |
| `+0x3B` | MV（移动力） |
| `+0x40/+0x42` | 当前/最大 HP |
| `+0x44/+0x46` | 当前/最大 MP |
| `+0x48/+0x4A/+0x4C/+0x4E` | 派生 AP/DP/DX/DE |

物品槽状态字节：

| 值 | 含义 |
|---:|---|
| `0x80` | 空槽 |
| `0x40` | **已装备**，参与属性计算 |
| `0x00` | 携带但未装备 |

- `rec_slot_claim()`：找第一个 `0x80` 空槽，写入物品 ID，状态置 0。
- `box_item_select()`：把选中槽置 `0x40`。
- `rec_slot_remove()`：删除该槽，后面的槽左移，最后槽置 `0x80`。
- 每个角色只有 **8 格**，**同种物品不堆叠**，每件占一格。

### 2.1 派生属性重算

`unit_recalc()`（`0x1145A`）：

```
派生AP = 基础AP + Σ(已装备物品[+1])
派生DP = 基础DP + Σ(已装备物品[+5])
派生DX = 基础DX + Σ(已装备物品[+3])
派生DE = 基础DX + Σ(已装备物品[+7])
```

只有 `slot[0] & 0x40` 的槽参与求和。

## 4. 装备限制与规律

### 4.1 职业限制

`box_item_usable()`（`0x1C1C3`）：

```c
cls = class_table[rec[0x20]];     // 0x6188A，7 字节/项
for (i = 0; i < 6 && cls[i] != 0xFF; i++)
    if (item[0] == cls[i]) return 1;
return 0;
```

每个职业最多允许 **6 种物品类型**。只检查类型，不检查等级、力量、性别、单件物品 ID。

### 4.3 同半区互斥

`box_item_select()`（`0x1C142`）按**物品 ID 的高位**分两半：

```c
if (item_id < 0x80)  → 清掉所有已装备的 item_id < 0x80 的 0x40
else                 → 清掉所有已装备的 item_id >= 0x80 的 0x40
```

因此角色同时最多：

- **1 件 ID < 0x80 的装备**（所有武器都在这半区）
- **1 件 ID >= 0x80 的装备**（防具、以及高编号消耗品/特殊品）

装第二把武器时，第一把武器会变成“携带未装备”（`0x40` 被清除），仍占格子但不加属性。装备本身没有“双手武器”设定；限制来自这个互斥规则。

### 4.4 购买/装备的其他限制

- 购买装备时，只有 `box_item_usable` 通过的角色才会出现在候选名单里（`shop_place_buy_run`）。
- 角色必须有**空物品槽**才能购买/获得装备。
- 装备/卸下通过背包菜单完成；`box_run` 在角色没有空槽时直接退出。
- 没有耐久度、重量、等级需求；转职道具是唯一的“等级相关”道具（见 §6）。

## 5. 武器规律

### 5.1 攻击距离

武器距离完全由物品表 `+11`（最小）/`+12`（最大）决定：

- 劍/刀：通常 `1/1`
- 槍/矛：通常 `1/2`
- 斧/鎚：通常 `1/1`（迴旋斧 `1/2`）
- 弓/弩：通常 `2/3` ~ `2/6`
- 杖/棍/爪：通常 `1/1`
- 機槍/光束炮：`2/4`、`1/2` 等

近战普通攻击在 `map_record_interact()` 中用第一个已装备武器（`rec_slot_find(rec,0)`，物品 ID < 0x80）的 `+11/+12` 选目标。AI 的 `map_ai_pick_reach_target()` 也使用同一对字段。

### 5.2 武器特殊效果

`map_attack_resolve()` 读取：

- `item[+9]`：攻击效果代码
  - `3`：HP 条扣减流程会执行两次（双段/吸血类）
  - `4`：暴击/额外效果，读取 `item[+10]` 增加概率
  - `2`：按 `item[+10]` 概率给目标附加状态（如麻痹）
- `item[+10]`：上述效果的概率值

### 5.3 暴击（致命一击）

物理攻击在 `map_attack_resolve()`（`0x1ECC7`）里先判定命中，命中后再判定暴击：

```c
crit = class_crit_table[rec[0x20] - 1];     // 0x524A8
if (weapon[9] == 4)
    crit += weapon[10];                     // 武器暴击加成
if (rand() % 100 < crit)
    defender_DP /= 2;                       // 暴击效果：防御减半
```

- 暴击率**只看职业**，再加武器 `+9/+10`；与等级、敏捷、运气无关。
- 暴击不是“伤害×2”，而是**目标 DP 减半**后再计算伤害。

职业基础暴击率（`0x524A8`，只列非 3% 的职业）：

| 职业 | 基础暴击 |
|---|---:|
| 忍者(23) | 30% |
| 武者(8) / 武聖(24) | 18% |
| 狙擊手(12) / 龍劍士(15) | 12% |
| 鬥士(16) | 10% |
| 神射手(20) | 7% |
| 英雄(17) | 6% |
| 劍士(1) / 弓兵(4) / 劍聖(9) | 5% |
| 其他职业 | 3% |

爪类武器的暴击相关字段：

| 武器 | `eff[9]` | `eff[10]` | 实际效果 |
|---|---:|---:|---|
| 鐵指套/鐵爪/皇帝指環/碎岩爪/金鋼指環/巨神指環 | 0 | 0 | 无暴击加成 |
| 毒爪/殭屍爪 | 2 | 20 | 不是暴击，是 20% 附加状态 |
| 裂刃爪 | 4 | 20 | **暴击率 +20%** |
| 魔龍爪 | 3 | 0 | 无暴击加成，但攻击结算两次（双段） |

所以凱麗（武者/武聖，基础 18%）：

- 普通爪：18%
- 裂刃爪：18 + 20 = **38%**
- 魔龍爪：18%，但一次攻击结算两次，至少出一次暴击约 `1-(0.82²) = 32.8%`

### 5.4 装备属性

装备只提供 AP/DX/DP/DE 四类加成（物品表 `+1/+3/+5/+7`），再经 `unit_recalc()` 汇总。  
武器主要给 AP/DX；防具主要给 DP/DE。没有“攻击力浮动”或“耐久”。

## 6. 转职道具

转职不是“装备”，而是 `item_menu_run()`（`0x2AA00`）里的特殊道具使用流程。

条件（`item_menu_list()`）：

- 角色等级 `rec[0x21] >= 20`；
- 当前单位类型 `rec[7] < 0x12`（未转职）；
- 角色自己的物品槽里持有对应转职道具；
- 使用后消耗该道具，并修改：
  - `rec[7] = 原类型 + 50`（新头像/单位类型）
  - `rec[0x20] = 新职业 ID`
  - 原 `rec[8]` 身份/名字不变

## 8. 敌人/NPC 的装备规律

### 8.1 模板来源

敌人/NPC 不是从“职业允许表”生成装备，而是从每个场景的状态头模板直接写入：

`unit_entry_build()`（`0x10C50`）：

```
state = dword_53A55 + 26*idx + 131
st[0] = 阵营（0 敌 / 1 友 / 2 我）
st[1] = 单位类型/身份 ID
st[4] = 等级
st[5..12] = 8 个物品 ID（0xFF = 空）
```

生成后：

- 槽 0/1：状态 `0x40`（装备）
- 槽 2..7：状态 `0x00`（携带，不参与属性）
- 空槽：`0x80`

因此**敌人的实际数值只吃前两件装备**；后面的格子是消耗品/战利品/剧情配置。

### 8.2 统计结果

扫描全部 FDFIELD 状态模板（1887 条记录；敌 1742、友 125、我 20）：

- 敌方非空物品槽数量：
  - 2 件：1665 条（绝对主流）
  - 1 件：19 条
  - 3 件：40 条
  - 4/5/6 件：各 1 条
  - 8 件：15 条
- 前两件装备组合：
  - **武器 + 防具：1715 条**
  - 仅防具：19 条（例如部分士兵模板没有武器）
  - 武器 + 宝石/特殊：8 条

### 8.3 规律

1. **普通敌人 = 一把武器 + 一件防具**  
   例如：
   - 盜賊(96)：闊劍 + 皮甲
   - 獸人(102)：盜賊匕首 + 盜賊之衣
   - 機甲兵(111)：光束劍 + 重裝甲
   - 機甲射手(114)：狙擊槍 + 突擊裝甲
   - 黑暗騎士(85)：惡魔之矛 + 黑暗鱗甲
   - 龍騎士(86)：龍之槍 + 力量鎖甲

2. **敌人模板不检查玩家职业表**  
   `unit_entry_build()` 直接写物品槽，不调用 `box_item_usable()`。  
   所以会出现“盜賊拿闊劍”（玩家盜賊职业只允许类型 2）这种配置；敌人装备是关卡作者配置，不是按玩家职业规则筛选的。

3. **额外槽通常是消耗品**  
   例如：
   - 精英戰士：武器 + 防具 + 藥草/回復劑
   - 黑暗戰士：戰士劍 + 銀鎧甲 + 再生藥
   - 機甲守衛：光束劍 + 特殊裝甲 + **6 个修理套件**（每个治疗 500）
   - 狂戰士：大地之劍 + 重鎧甲 + 神聖之水

4. **Boss/精英可能携带稀有道具**  
   例如 state 14 的獸人模板携带：
   - 光之眼(211)
   - 飛龍卵(205)
   - 聖者之戒(88)
   
   水魔神模板携带冰之眼(213)。  
   这些是模板配置；是否掉落由剧情/事件逻辑另行决定，不能只凭敌人背包判断。

5. **只有前两件计入战斗数值**  
   后续槽即使放了高属性武器/防具，也不会获得 `0x40` 装备态，因此不加 AP/DP/DX/DE。敌人 AI 可能把额外槽中的消耗品用于 `item_use`/AI item 逻辑，但不会把它们当装备。

### 10.2 有条件加入

#### 鐵諾（id 2，state 2）

`scene_state_02`（`0x230F2`）：

```c
if (rec_flag(6) == 0) {
    place_records(...);
    vm(7);
    unit_add(2);
}
```

- `rec_flag(6)` 是“鐵諾是否存活/未被标记”的分支；为 0 时加入。
- 这就是之前修过的漏掉 `unit_add(2)` 的位置（`0x231AF`）。

#### 凱麗（id 12，state 6）

`scene_state_06`（`0x232E8`）：

```c
if (dword_53AD5[17] == 1 && rec_flag(43) == 0)
    unit_add(12);
```

- `record 43` 就是本场景中的凱麗本人（uid 12、友军、Lv10）。
- `dword_53AD5[17]` 是她的隐藏事件标志；由 `funcs_1199C[25]`（`ev6_34C7A`）设置，
  该 handler 还要求 `dword_53AD5[16] == 1`。
- 因此条件可以理解为：**完成凱麗相关事件（flag17=1），且凱麗未被标记为失效/离场
  （record43 的 flag bit0 = 0）**。

#### 蜜蒂（id 18，state 15）

`scene_state_15`（`0x23A0A`）：

```c
count = Σ rec_flag(66..73);
if (dword_53BEF > 18 || count > 4 ||
    record0->max_hp(+0x42) < 320)
    不加入;
else
    unit_add(18);
```

加入条件：

- 当前地点 `dword_53BEF <= 18`；
- records 66..73 这 **8 名友军士兵**（uid 68、Lv24）中，`rec_flag` 置位的数量 `<= 4`；
- **record 0 的最大 HP `+0x42` >= 320**（通常就是索爾的 MHP，相当于等级门槛）。

> 修正记录：端口原来的 C 写成 `*(uint16_t*)dword_53A45 < 0x140`，读成了 record0 的
> x/y 字节；原机器码是 `movzx eax, WORD [eax+0x42]`。现已改为读取 `+0x42` 最大 HP。
> 这会影响蜜蒂的实际加入判定。

#### 羅德曼（id 19，state 22）

`scene_state_22`（`0x24754`）：

```c
if (unit_exists(18))          // 蜜蒂已在队伍
    rec_flag_set1(17);
else if (dword_53BEF < 15)
    unit_add(19);
```

- 加入条件：**蜜蒂(18)不在队伍**，且当前地点 `dword_53BEF < 15`。
- 如果蜜蒂已经加入，则不会加入羅德曼，而是设置 record17 的 flag。

#### 卡里斯（id 22，state 22）

```c
if (sub_24B14(100) != -1)
    unit_add(22);
```

- `sub_24B14(100)` 扫描 records 0..15 的物品槽，检查是否有人持有 **item 100
  天空之鑰**。
- 因此卡里斯加入条件：**队伍中任意一名角色持有天空之鑰**。

#### 達克塞（id 28，state 19）

`scene_state_19`（`0x23E74`）：

```c
unit_add(25);                 // 謝多必加入
if (dword_53BEF <= 15) {
    ... 剧情 ...
    unit_add(28);             // 達克塞
}
```

- 加入条件：当前地点 `dword_53BEF <= 15`。

### 10.3 六眼 → 天空之鑰 → 卡里斯

`scene_state_20`（`0x240FA`）在离开 state 20 时：

```c
for (i = 0xD1; i < 0xD7; i++)      // 209..214
    for (j = 0; j < 16; j++)
        if (record j 持有 item i) count++;
```

六件道具是：

| ID | 道具 |
|---:|---|
| 209 | 黃金徽章 |
| 210 | 星之眼 |
| 211 | 光之眼 |
| 212 | 暗之眼 |
| 213 | 冰之眼 |
| 214 | 火之眼 |

如果 records 0..15 合计持有全部六件：

1. 六件全部从对应角色物品槽中移除；
2. `sub_1C220(100)` 给第一个有空格、`+6 == 2` 的角色加入 **item 100 天空之鑰**；
3. 之后到 state 22 时，卡里斯因“队伍持有天空之鑰”而加入。

所以这条隐藏链是：

**收集六眼 → state20 换天空之鑰 → state22 卡里斯加入**

羅蘭/希爾法本身不要求六眼，他们在 state20 无条件加入。

### 10.4 莎拉与巴拿羅西亞

- 莎拉(id 20)：`funcs_1199C[50]` → `ev2_355B7`（`0x355B7`）里 `unit_add(20)`。
- 巴拿羅西亞(id 27)：`funcs_1199C[46]` → `ev2_35422`（`0x35422`）里 `unit_add(27)`。

这两个 handler 只负责播放一段加入演出再 `unit_add`。  
但静态扫描 FDFIELD 的：
- 单位模板 `st[22]` 脚本操作（op=2, arg=46/50）；
- 地图事件表 `+0x53` 的 kind/value（value=46/50）；

都**没有找到可达的引用**。也就是说，以当前数据表来看，这两个 handler 没有静态触发点：
可能是未启用的残留内容，或由尚未定位的动态脚本触发。  
**不能从现有源码/数据确认莎拉和巴拿羅西亞的实际加入条件。**
